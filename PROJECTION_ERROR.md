# Projection Error

## Core Claim

Projection error occurs when a local witness artifact is mistaken for the native resolving structure.

A projection may help a witness navigate a surface.

It may not govern lawful continuation.

---

## Native Object Versus Projection

The native object is:

```text
lawful consequence-resolution geometry
```

A projection is any local surface that shows only a slice of the resolving field.

Examples include:

```text
2D diagrams
timelines
dashboards
commit graphs
approval flows
case pages
policy tables
audit trails
public links
logs
reports
receipts without admissibility reconstruction
```

A projection can witness.

It cannot carry the total relation.

---

## Why Projection Error Matters

Projection error creates false governance.

A diagram can appear complete while standing remains unresolved.

A dashboard can expose state while failing to govern consequence.

A commit graph can show mutation order while failing to prove lawful continuation.

An audit trail can record history while failing to prove that failed movement was prevented from acquiring consequence status.

A receipt can preserve a terminal decision while failing to preserve admissibility differentiation.

---

## Non-Reduction Rule

Do not reduce lawful movement geometry into its projection artifacts.

The following are not the native object:

```text
policy approval
binary permit / deny logic
workflow state
commit eligibility
monitoring surface
risk score
dashboard state
linear timeline
2D explanatory model
```

The formal object is the resolving field in which movement either holds under lawful continuation conditions or it does not.

---

## Witness Projection Rule

A witness projection is permitted only when it remains subordinate to the resolving field.

```text
Projection may explain.
Projection may not replace.
```

A projection becomes dangerous when it is treated as proof of governance.

---

## Relation to Replay

Execution replay may reproduce a terminal outcome.

Legitimacy replay must reconstruct the admissibility state.

Projection error occurs when outcome replay is mistaken for legitimacy replay.

```text
same outcome != same admissibility
same terminal state != same lawful movement path
same refusal != same preserved boundary logic
```

---

## Relation to Field Laws

Projection error violates the field laws when a local surface is allowed to stand in for the kernel.

The kernel rule remains:

```text
BIND(M) is defined only when K(M) = ALLOW.
```

A projection cannot establish `K(M) = ALLOW` unless it preserves the required field invariants.

---

## Doctrine

The proof is not that a surface exists.

The proof is that the surface preserves the relation required for lawful continuation.

```text
A projection may witness consequence-resolution.
It does not become consequence-resolution.
```
