# Legitimacy Replay Separation

## Core Claim

Execution replay and legitimacy replay are not the same proof class.

A runtime can reproduce the same terminal outcome while losing the lawful basis that allowed or refused the movement.

The system must preserve admissibility differentiation, not merely outcome consistency.

---

## The Failure Surface

A replay system may prove:

```text
same terminal state
same output
same refusal label
same recorded decision
same visible effect
```

while failing to prove:

```text
same authority standing
same evidence freshness
same lineage condition
same admissibility state
same trajectory validity
same witness basis
same consequence-boundary reasoning
```

That is execution replay without legitimacy replay.

---

## Why Outcome Replay Is Insufficient

Same outcome does not imply same lawful path.

Same refusal does not imply same admissibility basis.

Same receipt does not imply same consequence-state truth.

Same terminal state does not imply same movement geometry.

A system that can replay outcome but cannot reconstruct the admissibility basis is preserving history while losing governance.

---

## Formal Distinction

Let `Replay_E` mean execution replay.

Let `Replay_L` mean legitimacy replay.

```text
Replay_E(M) = reproduced terminal behavior
Replay_L(M) = reconstructed admissibility state and lawful movement basis
```

Execution replay verifies what happened.

Legitimacy replay verifies why the movement was allowed, refused, redirected, escalated, halted, or partially admitted.

```text
Replay_E(M) does not imply Replay_L(M)
```

---

## Required Preservation

A legitimacy replay object must preserve or reconstruct:

```text
movement object
origin state
target state
authority standing
evidence freshness
lineage condition
recovery posture
consequence exposure
witness / replay object
trajectory validity
admissibility distance
law / policy version
kernel resolution
protected effect status
```

If replay cannot reconstruct these fields, it is not a legitimacy witness.

---

## Relation to Receipts

A receipt is not governance by itself.

A receipt becomes governance evidence only when it preserves the admissibility path.

A receipt that records only the final decision is a projection artifact.

It may document execution.

It does not prove consequence-bound movement governance.

---

## Relation to Projection Error

Projection error occurs when execution history is mistaken for legitimacy proof.

Examples:

```text
audit trail mistaken for custody
receipt mistaken for admissibility
terminal decision mistaken for lawful path
outcome replay mistaken for legitimacy replay
```

A witness projection must remain subordinate to the resolving field.

---

## Replay Requirement

Legitimacy replay must verify the same admissibility state, not merely the same terminal outcome.

If replay can reproduce refusal but cannot reconstruct why the movement lacked standing, it preserves execution history while losing consequence-state truth.

---

## Doctrine

The proof is not that the runtime can repeat what happened.

The proof is that the runtime can reconstruct the lawful basis under which movement acquired or failed to acquire consequence status.

```text
same outcome != same admissibility
same receipt != same legitimacy
same terminal state != same lawful movement path
```
